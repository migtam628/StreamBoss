# StreamBoss: notes for Claude

## Versioning: bump with every feature
Every feature or fix gets a new version, in the same commit as the change:
1. Set `version: X.Y.Z+1` in `pubspec.yaml` (patch bump per feature or fix, e.g. `0.2.3` -> `0.2.4`; minor for a big milestone;
   betas on the way to a milestone are tagged `v0.3.0b1`, `v0.3.0b2`, ... while pubspec holds `0.3.0`).
2. Add a `## X.Y.Z - YYYY-MM-DD` section at the top of `CHANGELOG.md` (it becomes the release notes). Betas: `## 0.3.0b2 - date`.
3. `test/version_test.dart` fails if pubspec and the top changelog entry disagree or the order is wrong.
4. Tell the user the tag to create. My tag push gets 403, so give them: `git fetch origin && git tag -a vX.Y.Z <sha> -m "StreamBoss vX.Y.Z" && git push origin vX.Y.Z`.
Never reuse or move a tag. Details: README "Versioning".

## Working in this repo
- Platform folders (android/, macos/, ...) are generated by `flutter create` and gitignored; `tool/patch_*.dart` adjust them.
  `flutter create` also rewrites `analysis_options.yaml` and adds `test/widget_test.dart`: restore/delete those before committing.
- Do not run `dart format` over the repo (it is not formatted that way and the diff explodes); format only files you create.
- Gate before pushing: `flutter analyze` (clean) and `flutter test`. Check CI after each push; the build job also runs on Android, macOS, Windows, Linux, web, Roku and tvOS.
- Branch: develop on `claude/cross-platform-media-app-o0v8rc`; do not open a PR unless asked.
- Never put provider credentials in code, tests or commit messages.
