# Changelog

Every feature or fix gets its own version, newest first. The heading is the git tag without the `v`
(`## 0.2.3` is tag `v0.2.3`) and its section becomes that release's notes. Betas look like `0.3.0b2`
and sort before their final release. See "Versioning" in README.md.

## 0.3.0b56 - 2026-10-17
- **streamboss.site now comes in English and Spanish.** The page has an **EN | ES** switch in the header. It opens in Spanish for a visitor whose browser is set to Spanish, in English otherwise, and remembers the choice; a link ending in `?lang=es` (or `?lang=en`) opens that language whatever the browser says, handy for sharing with clients. Everything is translated: the headline, the features, "What it is not", the questions, the footer, the picture descriptions for screen readers, the page title and the preview text when the link is shared, and the whole **Install** panel (each device's steps, notes and download buttons, plus Copy code). English stays in the page itself, so it still works without JavaScript. `tool/test_site_i18n.py` (run by the Build workflow) fails if a text on the page has no Spanish, or a device's Spanish steps do not match the English ones. The page itself reaches https://streamboss.site when `main` is moved to a tagged version, as for every website change.

## 0.3.0b54 - 2026-10-14
- **The web app's blocked-request message is right for a server on your own computer.** For an address like `http://127.0.0.1:18001` it said "plain http address on a secure page", but a browser lets a secure page reach your own computer over http: what blocked it (the console said so) was CORS, the server not saying websites may read it. The message now says that, names the headers the server would need (`Access-Control-Allow-Origin`, and `Access-Control-Allow-Private-Network` for a page on the internet) and that running the web app from the same computer or using the app avoids it. An address on a home network (`192.168.x.x`) is still reported as plain http, which a browser does block. The address in these messages never shows the login.
- **Caddy no longer goes blind when the web app folder is replaced.** After b52's page publish deleted `webapp/` and it was made again, Caddy kept looking at the old folder and answered 404 even once the files were back, because Docker had mounted `webapp/` itself. The web app is now served from the whole website folder (`/srv/web/webapp`, the mount the website already uses), which never goes away, so a publish cannot leave it stale (a test checks the mount and the Caddy root). On a server set up with b51 to b53 this needs the two small files replaced (`sites/webapp.caddy` and `docker-compose.webapp.yml`, as in the b53 steps) and Caddy recreated once with `docker compose up -d`. No change to the apps.

## 0.3.0b51 - 2026-10-13
- **StreamBoss on the web, at https://web.streamboss.site.** For people who would rather not install the app: the same app in a browser. Every tagged release now sends its web build to your server along with the downloads (the same restricted key, no new GitHub secret), and a new Caddy site (`server/sites/webapp.caddy`, switched on with `server/docker-compose.webapp.yml` and `WEBAPP_DOMAIN`) serves it: any address that is not a file opens the app, the files that start it are always checked fresh so a new release is picked up at once, and the big engine and picture files are kept for a day. Both used to show "ClientException: Failed to fetch". The web app now says which server it could not read, that it is probably one of those two rules, and that the StreamBoss app for your device does not have them. This also covers the guide: a guide file on a server without CORS (for example `worker-….onrender.com/guide.xml.gz`) is now explained instead of shown raw. The apps are unchanged.

I checked the files and the whole git history for keys, tokens, passwords, addresses and e-mails before this: nothing was found. A test that named a real provider's host now uses a neutral one. The LICENSE and README now say the source is published to be read, not licensed for reuse (all rights reserved).
  - **There is no proxy on purpose:** one that fetched any address for anyone would be an open relay for your server. So the web app suits providers with an https address that allows websites; for the others people need the app.
  - **Checked:** the Caddy site was validated and run against the real web build (any address opens the app, no-cache on the start files, a day for the engine, the right type for the engine file); the upload script's syntax and the messages (a blocked https server, a blocked plain-http address, a page that is not secure, and outside a browser) are covered by tests. **Not run on your server yet**: it needs the DNS record, the folder and a release.

## 0.3.0b50 - 2026-10-13
- **Fix: the web app could not load a library.** After the provider answered (every request returned 200) the web app stopped with "Unsupported operation: new RawReceivePort" and showed the sign-in form again. Since b25 a large answer (over 200 KB, which is any real library) was parsed in a background isolate, and a browser has no isolates. The web app now parses on the page's own thread (the other apps keep the background isolate). Phones, tablets and computers were not affected.
  - **Checked:** which parses go to an isolate (and that the web app never does) is covered by tests. **Run in a browser here:** the web build loaded a 4,000-title library from a stand-in provider and showed Home. Please hard-refresh your web app and connect your own provider; a big library now parses on the page's own thread, so the page may pause for a moment while it does.

## 0.3.0b25 - 2026-10-10
- **A much faster start.** Before, the app waited for the provider to send its whole library (often tens of megabytes) and then turned it into 100,000 or more items on the screen's own thread, so a Fire Stick showed nothing for many seconds and froze while it worked. Now:
  - **The app opens at once.** It no longer waits for the library.
  - **The library is saved on the device** (compressed, in the app's private folder; about 2 MB for 150,000 titles) and shown from that copy on the next start, while the provider's current library is fetched quietly behind it. Your phone opens a small page served by the app on your home network and sends the login back, so there is no typing with a TV remote. The server stops when the screen closes or after 10 minutes and locks after 5 wrong PINs. Native apps only.
- macOS: adds the `network.server` entitlement the phone-setup page needs; CI checks for it.
- Versioning: betas (`v0.3.0b2`) and release candidates are accepted as tags and published as pre-releases; About shows the full version; "Check for updates" offers newer betas to beta builds and only stable releases to stable builds; release notes come from this file.

## 0.2.2 - 2026-10-05
- TV mode, on automatically for Android TV, Google TV and Fire TV (Settings > Appearance > TV mode forces it on or off): 20% larger text and posters, a bold white focus ring with glow, a side rail, safe screen margins, the cursor starting on Play, an "Add to My list" button on movie pages, first episode focused, and Back returning to Home before it leaves the app.

## 0.2.1 - 2026-10-05
- Connections try IPv4 first and report the real error. Dart used to show the first failure, which on networks without IPv6 is an instant "Network is unreachable" that hid what actually went wrong.
- Settings > Network > Test connection: a credential-free report of DNS, per-address connects and an HTTP request to your provider, with a Copy button.
- "Network is unreachable" and "No route to host" errors now explain themselves.

## 0.2.0 - 2026-10-05
- Settings area with eight sections: source and library, playback, subtitles, appearance, library and guide, network and metadata, data and backup, about. Every option changes behaviour: resume, seek and skip steps, controls auto-hide, audio and subtitle languages, decoder and buffer, subtitle styling, text and poster size, start screen, adult filter, A-Z sort, 24-hour clock, User-Agent, TMDB key, backup and restore, clearing history, update check.
- Fixed the player's on-screen back arrow, which only hid the controls.
- Movie and series pages show poster, plot, cast, runtime and trailer from the provider (merged with TMDB when a key is set).
- The guide downloads when you open the Guide tab instead of at login.
- A `get.php?username=..&password=..` link now uses the provider's Xtream API.
